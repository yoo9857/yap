# CraftYap 기계 물리 시스템

## 제품 원칙

플레이어가 부품을 조립하고, 무게·배치·추진 방향을 바꾸면서 작동 원리를 발견하는 제작 게임이다. 자동차와 비행체는 별도의 이동 스크립트가 아니라 같은 설계도와 물리 규칙을 사용한다. 실제 과학과 게임을 위한 근사를 구분하고, 구현하지 않은 현상을 구현했다고 표현하지 않는다.

이 문서는 현재 구현의 운영 기준이다. 대형 게임 수준의 모든 기능이나 품질 인증을 의미하지 않는다.

## 기술 스택과 책임

현재 저장소에 설치된 버전을 기준으로 한다.

| 계층         | 기술 / 파일                                       | 책임                                                      |
| ------------ | ------------------------------------------------- | --------------------------------------------------------- |
| 데이터       | TypeScript, `craft/machines/blueprint.ts`         | 부품 정의, 좌표, 연결 검사, 질량·무게중심, 설계도 직렬화  |

의존성 방향은 `규칙·공기역학 → 설계도 → 시뮬레이션 → 제작실 → 게임 연결`이다. 시뮬레이션·임무·공기역학은 DOM, 키보드, localStorage를 알지 않는다. `library.ts`는 이 모드에서 localStorage를 만지는 유일한 파일이다. Three.js의 벡터·쿼터니언 수학은 사용하지만 renderer는 사용하지 않는다. 다른 모드는 `Blueprint + VoxelWorld + 시작 위치 + MachineInput`으로 같은 물리를 재사용할 수 있다.

## 단위와 실행 계약

- 길이 m, 질량 kg, 시간 s, 힘 N, 토크 N·m, 각도 rad. HUD에서만 m/s를 km/h로 바꾼다.
- `PHYSICS_RULES`와 `AIR`를 튜닝의 기준으로 삼는다. 중력은 9.81 m/s², 시뮬레이션 간격은 1/60초, 공기 밀도는 1.225 kg/m³로 고정한다.
- 렌더링 프레임 수가 달라도 `GameLoop`의 고정 틱에서만 물리를 전진시킨다. 긴 정지 후의 누적 시간은 기존 루프 정책에 따라 버린다.
- 부품은 격자 1칸 단위로 연결한다. 하나의 연결된 기계는 하나의 복합 강체이며 각 부품의 질량을 합산한다.
- 추진기는 월드 방향으로 변환한 힘을 장착 위치에 적용한다. 무게중심에서 벗어난 힘은 회전을 일으킨다. 기체 위치를 직접 더해서 비행시키지 않는다.
- 날개와 기구도 같은 규칙을 따른다. 장착 위치의 속도(`v + ω × r`)로 힘을 계산하고 그 위치에 적용하므로, 꼬리날개는 회전을 줄이고 바깥 날개는 기체를 굴린다.
- 바퀴는 Rapier의 raycast vehicle controller로 접지, 서스펜션, 구동, 제동, 앞바퀴 조향을 처리한다.
- 자이로는 회전 입력과 각속도 감쇠를 제공한다. 자동 수평이나 자동 고도 유지가 아니다. 감쇠만 있으므로 무게중심을 벗어난 추력은 `토크 / 감쇠` 속도의 일정한 회전으로 남는다. 예제 설계도는 이 때문에 추력선과 무게중심을 맞춰 두었다.
- 지형은 현재 복셀 데이터를 사용한다. 이웃한 동일 기둥을 상자로 합치며 동굴·문·빈 공간을 보존한다. 기계 주변 3×3개의 16칸 청크만 유지하고 이동 시 갱신한다.
- 고도는 절대 높이가 아니라 바로 아래 지형 기둥의 윗면 기준이다(`surfaceY + 1`).
- 시험 중에는 복셀 채굴/설치를 막는다. 시험을 다시 시작할 때 현재 지형을 다시 읽는다.
- 시험장은 섬 북쪽 평지의 평탄한 구간(79.5, 18.5)이다. 약 48 m 직진 구간을 확보하기 위한 선택이며, 성 주변에서는 몇 초 만에 단차에 막힌다.

## 설계도, 보관함, 공유

- 설계도 스키마 `version: 1`과 물리 규칙 `revision: 1`은 별도다. 구조 변경과 움직임 변경을 구분한다.
- `craftyap-machine-blueprint-v1`에 현재 설계도를 자동 저장한다. `craftyap-machine-library-v1`에 보관함 12칸, `craftyap-machine-missions-v1`에 임무·기록을 저장한다. 기존 섬 세이브와 독립적이다.
- 공유 코드는 `CYM1.<부품당 5글자>.<이름>` 형식이다. 부품 종류·좌표·방향을 36진수 한 글자씩 담아 128부품도 한 줄에 들어간다. 서버 백업이나 계정 연동은 아직 없다.
- 저장소에서 읽은 값과 붙여넣은 코드는 모두 `validateBlueprint`를 통과해야 편집기나 엔진에 도달한다.
- 미완성 설계도도 저장할 수 있지만 시험 운전은 연결성과 조종석 검사를 통과해야 한다.
- 부품 최대 128개, 각 축 좌표 -12~12, 조종석 1개. 겹치는 부품이나 잘못된 부품 종류는 거부한다. 조종석을 다시 놓으면 기존 조종석이 옮겨 간다.
- 최근 편집 30개까지 실행 취소하고 다시 실행할 수 있다. 시험을 정지하면 원래 설계도로 돌아오며 시험 중 위치·속도는 저장하지 않는다.
- 튜닝을 바꾸면 규칙 revision, 시험 기대값과 변경 이유를 함께 갱신한다. 스키마를 바꿀 때는 기존 세이브의 migration 시험이 필요하다.

## 플레이 흐름과 화면

- 패널 맨 위의 **바로 타기**는 예제 자동차/비행기를 불러와 **곧바로 시험 운전까지 시작한다.** 아무것도 만들지 않고 먼저 몰아볼 수 있어야 조작을 배울 수 있기 때문이다.
- 제작 콘솔은 `부품 / 설계도 / 임무` 세 탭이다. 부품 선택은 숫자 1~8, 방향 회전은 `R`, 좌우 대칭은 `M`, 지우개는 `X`, 화면 맞추기는 `F`, 실행 취소·다시 실행은 `Ctrl+Z` / `Ctrl+Y`다.
- 좌우 대칭은 x≠0 칸에 붙일 때 반대편에도 같은 부품을 놓고, 좌우 방향만 뒤집는다. 제거할 때도 짝을 함께 지운다.
- 고스트는 실제 부품 모델이며 방향이 있는 부품에는 화살표가 붙는다. 지우개 상태에서는 지워질 부품이 붉게 표시된다.
- 통계는 부품 수·질량·바퀴 수·날개 면적과 두 개의 계기다. 상승력은 `상승 추력 / 무게`, 안정성은 무게중심이 바퀴 바닥면 안쪽으로 얼마나 들어와 있는지(칸)다. 안정성은 바퀴가 3개 이상일 때만 의미가 있다.
- 시험 운전 중 조작키 안내는 그 기계가 실제로 반응하는 것만 보여준다. 바퀴가 없으면 주행 키를 설명하지 않고, 상승 추진기가 없으면 상승 키를 설명하지 않는다.
- 시험 운전 중에는 `C`로 추적·자유·조종석 시점을 바꾸고, `R`로 제자리에 되돌리며, `Enter`로 제작으로 돌아온다. 추적 시점은 요(yaw)만 따라간다. 피치·롤까지 따라가면 보기 어려워지므로 자세는 HUD의 수평계가 대신 보여준다.
- 주행 HUD는 속도계, 고도·기울기·시점, 바퀴 접지 표시, 추진·상승·부스터 막대, 수평계로 구성한다. 임무 진행률은 오른쪽 위에 실시간으로 쌓인다.
- 먼지와 엔진 소리는 연출이며 시뮬레이션에 되먹임하지 않는다. 브라우저가 오디오를 거부하면 조용히 넘어간다.
- 처음 제작실을 열면 3단계 안내가 한 번 표시되고 `craftyap-machine-coach-v1`에 기록된다.

## 조작 보조 (초보 자동조종)

보조는 **물리가 아니라 자동조종**이다. 새로운 힘을 만들지 않고, 기계가 이미 가진 **자이로 토크와 상승 추진기 스로틀만** 조작한다. 따라서 보조는 그 설계도가 원래 할 수 있는 일만 할 수 있다.

- **자동 수평** — 공중에 있고, 플레이어가 기울기/롤을 건드리지 않았고, 기울기가 `levelLimit`(1.45 rad) 안일 때만 동작한다. 기체의 위 방향 벡터를 월드 위쪽으로 되돌리는 축(두 벡터의 외적, 크기는 sin(기울기))으로 토크를 걸기 때문에 수평에 가까워질수록 보정이 저절로 사라진다. **자이로가 없는 기계는 수평을 잡지 못한다.**
- **고도 유지** — 상승 추진기의 스로틀을 자동으로 맞춘다. 무게를 정확히 상쇄하는 스로틀(`hoverBias = 무게 / (상승추진기 수 × 추력)`)을 앞먹임으로 쓰고, 목표 상승률과 실제 수직 속도의 차이에 비례항을 더한다. `hoverBias`가 1을 넘는 기계, 즉 **자기 무게를 못 드는 기계는 보조를 켜도 그대로 가라앉는다.**
- **상승/하강** — 보조가 켜져 있으면 Space는 `climbRate`(6 m/s), Ctrl은 `descendRate`(-4 m/s)를 목표로 하는 **요청**이고, 스로틀은 자동조종이 만든다. 보조를 끄면 Space는 예전처럼 추진기 100%의 원시 입력으로 돌아간다. 즉 보조를 끈 상태의 거동은 보조 도입 이전과 완전히 동일하다.
- 바퀴가 지면에 닿아 있으면 보조는 개입하지 않는다. 경사면에 선 자동차는 경사면에 서 있어야 한다.
- `G`로 언제든 켜고 끌 수 있고 `craftyap-machine-assist-v1`에 저장된다. 기본값은 켜짐이다.

보조를 끈 상태가 이 문서의 나머지가 설명하는 모델이다. 튜닝은 `PHYSICS_RULES`가 아니라 `ASSIST`에 모여 있으므로, 물리 수정과 난이도 조정은 서로 섞이지 않는다.

## 시험 운전 임무

임무는 "어떤 부품을 썼는가"가 아니라 "기계가 무엇을 했는가"로만 판정한다. `MissionRun`은 텔레메트리와 `dt`만 받는 순수 누적기이며 완료 순간에만 해당 임무 id를 돌려준다.

| id             | 목표             | 판정                                                |
| -------------- | ---------------- | --------------------------------------------------- |
| `first-roll`   | 40 m 이동        | 출발점에서의 수평 거리                              |
| `speed-run`    | 55 km/h          | 최고 속력                                           |
| `hill-climb`   | 고도 +10 m 접지  | 출발 높이 대비 상승 + 접지 상태                     |
| `hover`        | 20 m에서 3초     | 지형 위 20 m 이상을 연속 3초 유지                   |
| `soft-landing` | 2.5 m/s 이하 접지 | 15 m 이상 떠 있다가 느리게 착지                     |
| `long-haul`    | 누적 300 m       | 한 번의 시험 운전 누적 이동 거리                    |

한 틱에 5 m 이상 움직인 구간은 누적 거리에서 제외한다. 제자리 복귀(`R`)나 범위 이탈 복귀로 거리를 벌 수 없게 하기 위한 조건이다.

## 예외와 수명 관리

| 상황                          | 처리                                                 |
| ----------------------------- | ---------------------------------------------------- |
| 잘못된 JSON, 버전, 좌표, 부품 | 로더가 거부하고 기본 설계도로 진입                   |
| 잘못된 공유 코드              | 거부하고 현재 설계도 유지, 원인 안내                 |
| 연결이 끊김, 조종석 누락/중복 | 편집 유지, 시험 실행 차단, 원인 안내                 |
| NaN/Infinity 조작             | `INVALID_INPUT`, 엔진에 입력하기 전에 차단           |
| 숫자가 유효한 입력 범위 초과  | -1~1, 상승 입력은 0~1로 제한                         |
| 비정상적으로 큰 공기력        | 부품당 9000 N으로 제한해 솔버 폭주를 막음            |
| 유효하지 않은 강체 상태       | `NON_FINITE_STATE`, 시험 중단, 제작 상태 복원        |
| WASM 로딩 실패                | 안내 표시, 다음 실행에서 로딩 재시도                 |
| 준비 중 제작실 종료           | 세대 번호로 늦게 완료된 시작 요청 무효화             |
| 저장 공간 부족/접근 거부      | 플레이 유지, 저장 실패 안내                          |
| 창 포커스 상실/숨김           | 조작 키 비워서 무한 가속 방지                        |
| 시험 범위 이탈                | x/z -20~180, y -15~250을 벗어나면 **출발점으로 복귀** (시험은 계속) |
| 시험 종료/모드 해제           | Rapier world 해제, 오디오 정리, 이벤트·화면·GPU 리소스 수명 정리, 카메라 fov 복원 |

시험에서는 플레이어를 기존 위치에 멈춰 두고 기계 카메라를 사용한다. 아일랜드로 돌아오면 기계 시뮬레이션은 종료되고 그 회차의 기록이 병합된다. 영구 월드 차량, 플레이어 탑승 충돌, 멀티플레이 권한 처리는 후속 단계다.

## 검증과 유지보수

`pnpm --filter @robo/client test:physics`는 설계도 검증, 질량, 착지, 4륜 접지, 구동·조향·제동, 상승·중력 복귀, 비대칭 추력의 회전, 날개 양력과 가장자리 흐름, 기구 부력, 제자리 복귀, 고도 기준, 벽 충돌, 고정 입력 재생, 비정상 입력 차단을 확인한다. 보조에 대해서는 기울어진 기체를 수평으로 되돌리는지, 끄면 기울어진 채로 두는지, 입력이 들어오면 즉시 비키는지, 자기 무게를 못 드는 기계는 보조를 켜도 떨어지는지, 접지한 자동차를 건드리지 않는지를 확인한다. `test/machine-build.test.ts`는 부품표·예제 설계도·임무 판정·보관함·공유 코드를 엔진 없이 확인한다. 기존 게임 테스트도 `pnpm --filter @robo/client test`로 실행한다.

`node tools/e2e-machines.mjs`는 실제 브라우저에서 단축키, 보관함, 공유 코드 왕복, 주행, 카메라 3종, 제자리 복귀, 추진 비행, 날개 활공, 재시작 후 기록 유지까지 확인한다.

변경 확인 순서:

1. 재현 조건과 규칙 변경 이유를 기록한다.
2. 실패를 드러내는 물리 시험을 추가/수정한다. 내부 메서드 호출 여부보다 이동·충돌·회전 결과를 검증한다.
3. 타입 검사, 물리 시험, 클라이언트 전체 시험, 변경 파일 lint, 빌드를 통과시킨다.
4. 제작실에서 부품 편집 → 저장 → 실행 → 정지 → 재편집 → 새로고침을 확인한다.
5. Rapier, 부품 질량, `AIR` 상수를 바꿀 때는 예제 세 종류(탐사차·비행체·활공기)를 모두 재검증한다.
6. 부품을 추가하면 `tools/generate-machine-assets.mjs`에 모델을 더하고 `pnpm assets:machines`로 다시 생성한다. `PART_ORDER`의 모든 부품이 GLB에 없으면 에셋 로딩이 실패한다.

`.github/workflows/physics.yml`은 PR과 관련 경로 변경에서 타입 검사·시험·빌드를 실행한다. 로컬 통과가 원격 CI 실행이나 배포 완료를 의미하지 않는다.

같은 엔진 빌드에서 고정 입력 재생을 검증한다. 서로 다른 브라우저·CPU 간의 비트 단위 결정성이나 멀티플레이 동기화를 보장하지 않는다. 향후 서버 권위 시뮬레이션, 리플레이 포맷, 플랫폼별 성능 예산은 별도 검증 후 도입한다.
