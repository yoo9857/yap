11월 11일 패치 노트 — 자동차·헬리콥터 모델과 기계 작업실 개편

자동차·헬리콥터 모델링과 기계 작업실 UI/UX, 블록별 커스텀을 개선했어요. 로딩·멀티플레이 추가 최적화의 검증 상황도 함께 안내해요.

자동차·헬리콥터 모델과 기계 작업실 개편 내용을 먼저 안내해요. 아래 '추가 최적화 · 배포 전 검증'에 있는 로딩·멀티플레이 개선은 로컬 검증 단계이며, 운영 반영 시 후속 패치노트로 알려 드릴게요.

요약한눈에 보기

자동차·헬리콥터 모델링, 기계 작업실 UI/UX, 블록 커스텀을 함께 개선했어요. 기계를 크게 살펴보면서 조립하고, 선택한 블록의 색과 성능을 바꾼 뒤 시험 운전까지 이어갈 수 있도록 화면 구성을 정리했어요.

자동차·헬리콥터 모델 실제 모습

자동차 블록 모델

자동차를 구성하는 블록 모델을 조립한 원본 렌더예요. 조종석의 유리와 핸들, 차체의 연결부, 바퀴의 트레드와 허브를 살펴볼 수 있어요.

Skylark 헬리콥터

운영 게임의 기계 작업실에서 촬영한 실제 Skylark 모델이에요. 아래 부품 목록에서 차체와 조종석, 엔진 팩, 로터, 스키드 등을 선택할 수 있어요.

BEFORE / AFTER

위 비교 이미지는 이전에 보관한 작업실 화면과 개편한 작업실의 UI/UX 구성을 보여줘요.

NEW새로 추가 2

  • Skylark 헬리콥터 모델전용 헬리콥터 모델과 예제를 기계 작업실에 연결했어요. 조종석, 엔진 팩, 메인 로터, 꼬리 로터, 스키드 등 실제 모델의 구성 부품을 살펴볼 수 있어요.
  • 헬리콥터 부품 살펴보기모델 부품을 선택하고 분해 보기로 각 부품의 배치와 연결 관계를 확인할 수 있어요.

실제 게임의 분해 보기를 켠 화면이에요. 조립 보기로 돌아가 완성된 모습과 비교할 수 있어요.

UP개선 13

자동차·헬리콥터 모델링

  • 자동차와 기계 블록 표현차체, 조종석, 바퀴, 추진기 등의 입체 표현과 부품 이미지를 다듬었어요. 화면에서 고르는 부품과 조립된 기계의 형태를 알아보기 쉬워졌어요.
  • 헬리콥터 표현로터와 조종석 문 등 모델의 움직임을 작업실과 시험 운전 상태에 맞게 연결했어요.
  • 기계를 크게 살펴보기중앙 미리보기 공간을 확보하고 정면·측면·위·전체 보기와 회전·확대 조작을 정리했어요.

기계 작업실 UI/UX

  • 작업별 화면 구성블록 조립, 블록 커스텀, 시험 운전, 설계도 보관함, 조작법을 각각의 화면으로 나눴어요.
  • 가로형 블록 팔레트조립 화면 아래에서 구조·구동·비행 부품을 골라 붙일 수 있어요. 부품은 실제 블록 이미지로 표시해요.
  • 버튼과 작업 순서 정리실행 취소·다시 실행·지우개와 시험 운전 버튼의 위치를 정리하고, 추가 도구와 복구 기능은 펼쳐서 사용할 수 있게 했어요.
  • 화면 크기 대응작은 화면에서도 주요 버튼과 미리보기 영역이 겹치지 않도록 배치와 간격을 다듬었어요.

블록 커스텀과 설계

  • 선택한 블록을 직접 커스텀조립된 기계에서 블록을 선택하고 외형과 성능을 바꿀 수 있도록 편집 흐름을 개선했어요.
  • 외형과 성능 설정 정리블록 색과 재료 무게, 바퀴 크기·접지력·서스펜션, 추진력, 날개 면적, 기구 부력 등 부품별 설정을 확인하기 쉽게 정리했어요.
  • 좌우 함께 편집대칭 편집을 기본으로 시작하고, 선택한 블록과 짝을 이루는 반대편 블록에도 설정을 적용할 수 있어요.
  • 균형과 추진 방향 안내무게중심과 기울기, 추진 방향을 눈으로 확인하면서 부품의 위치와 방향을 조정할 수 있어요.
  • 설계도 보관함저장한 기계의 미리보기와 불러오기·교체·삭제·복구 흐름을 정리했어요.

운영 게임에서 자동차의 차체 블록을 선택한 화면이에요. 선택한 부품의 색을 고르고, 좌우 블록에 함께 적용할 범위를 확인할 수 있어요.

시험 운전

  • 조작 보조와 시점주행·비행 조작 보조를 다듬고, 추적·자유·조종석 시점과 속도·고도·기울기 표시를 함께 사용할 수 있게 했어요.

추가 최적화 · 배포 전 검증

다음 항목은 개발 환경에서 수정하고 확인한 내용이에요. 운영 서버 반영을 준비하고 있어요.

작업실 성능

  • 작업실 대기 중 연산 감소미리보기가 바뀔 때 화면을 갱신하고, 작업실에서 필요한 지형 준비와 효과 갱신을 조정했어요.
  • 미리보기 자원 관리설계도 썸네일이 게임의 그래픽 자원을 재사용하도록 바꾸고, 작업실을 닫을 때 대기 작업과 임시 자원을 정리하도록 개선했어요.
  • 모델 로딩과 표시 비용 조정필요한 모델의 로딩 시점을 조정하고, Skylark의 메시와 반복 효과 처리를 최적화했어요.

멀티플레이 동작 수정

  • 시험 주행 중 친구가 멈춰 보이던 문제기계 시험 주행 중에도 다른 플레이어의 위치와 애니메이션을 계속 갱신하도록 수정했어요.
  • 지연이 오래 남던 위치 표시같은 오래된 위치를 반복해서 받았을 때 이동 표시의 대기 시간이 계속 늘어나던 문제를 수정했어요.
  • 여러 명이 한꺼번에 나타날 때의 순간 부하화면에 들어온 아바타부터 프레임당 하나씩 생성하도록 바꿨어요.
  • 연결이 밀릴 때 쌓이는 위치 전송다음 갱신으로 대체할 수 있는 위치 전송을 건너뛰어 오래된 움직임이 쌓이는 상황을 줄였어요.
  • 재접속 중 전송 순서교실 데이터를 다시 받는 동안의 게임 동작 전송을 제어하고, 복구 시 위치 보간 기준을 초기화하도록 수정했어요.
  • 작업실 안에서 계속 달리는 모습작업실을 연 상태에서는 다른 참가자에게 기본 대기 자세를 전달하도록 수정했어요.

최적화 검증 결과

  • 브라우저 두 대에서 위치 갱신에 40~180ms 지연을 넣고, 시험 주행 중 상대 캐릭터가 움직이는 것을 확인했어요.
  • 서버 재시작 후 교실과 저장된 블록이 복구되는 것을 확인했어요. 이후 네 번 재접속하는 동안 아바타가 중복 생성되지 않았고, 텍스처와 지오메트리 수가 일정했어요.
  • 관련 테스트 169개와 빌드·타입 검사를 통과했어요.

격리 서버에서 8개 방, 총 200명이 이동하고 블록을 편집하는 일반 부하를 약 16초씩 비교했어요. 아래 p99는 전체 측정의 99%가 해당 시간 이내였다는 뜻이에요.

  • 물 흐름이 많은 동시 작업물 흐름과 블록 편집을 함께 켠 200명·30초 검증에서는 연결을 모두 유지했지만, 이동 갱신 공백이 최대 1.84초 발생했어요. 이 지연의 원인 확인과 추가 개선이 남아 있어요.
